# Mirra 영상 발행 에이전트

PC에 저장된 영상 → 분석 → 캡션/해시태그 → Mirra 업로드·발행 → 기록까지 한 흐름으로 처리한다.
**반드시 사용자 PC에서 실행하는 Claude Code(또는 Claude Desktop)에서 사용한다.** 클라우드 세션은 PC 파일에 접근할 수 없다.

## 0. 사전 설정 확인 (매 실행 시작 시)

1. `mirra-publisher/config.json`을 읽는다. 없으면 `config.example.json`을 복사하도록 안내하고 **중단**한다.
   - `video_dir`: 발행 대기 영상 폴더
   - `accounts`: 발행할 계정 목록 (Mirra에 표시되는 계정명/핸들 그대로). **비어 있으면 중단** — 계정을 추측하지 않는다.
   - `brand`, `store`, `region`: 해시태그용 고정 정보 (영상에서 확인되지 않는 사실을 대체하지 않는다. 사용자가 직접 입력한 값만 사용)
2. Mirra 도구가 있는지 확인한다. 우선순위:
   1. **Mirra MCP** (`mcp__mirra__*` 등 Mirra 이름이 들어간 도구) — Mirra 설정 > API와 MCP > MCP 연동에서 등록
   2. **브라우저 제어** (Claude in Chrome / 내장 브라우저 / Playwright MCP) — https://www.mirra.my/ko/home
   - 둘 다 없으면 무엇이 필요한지 알려주고 중단한다.
3. 발행 기록 `mirra-publisher/publish-log.csv`를 읽어 이미 발행된 영상 목록을 만든다.

## 1. 영상 확인

```bash
python3 .claude/skills/mirra-publish/scripts/scan_videos.py
```

- 폴더 내 영상의 파일명, 길이, 해상도, 비율, 형식, 용량, SHA-256 해시를 출력하고 `publish-log.csv`와 대조해 `status`(new / published / check_needed)를 붙인다. `check_needed`는 이전 발행 결과가 unknown인 영상이므로 사용자 확인 전에는 발행하지 않는다.
- **파일명 또는 해시가 `success` 기록과 일치하면 건너뛴다.** 이름은 다르지만 해시가 같으면 중복으로 보고 발행하지 않는다.
- `new` 영상만 오래된 순으로 처리한다.

## 2. 영상 분석

```bash
python3 .claude/skills/mirra-publish/scripts/extract_frames.py "<영상 경로>"
```

- 균등 간격 키프레임(기본 8장)을 `mirra-publisher/work/<파일명>/`에 저장한다. Read 도구로 각 프레임 이미지를 직접 본다.
- 오디오가 있으면 `audio.wav`도 추출된다. `whisper`가 설치돼 있으면 `transcript.txt`를 만든다(없으면 음성은 "확인 불가"로 둔다).
- 정리할 항목: 핵심 주제 / 등장 제품·음식·매장·인물·서비스 / 화면 속 텍스트 / 음성·자막 / 분위기 / 강조할 포인트 / 키워드.
- **프레임과 자막에서 확인된 사실만 쓴다.** 가격, 메뉴명, 위치, 이벤트 등은 화면·음성·config에 없으면 쓰지 않는다.
- 내용을 판단하기 어렵다면(프레임이 모호, 무관한 영상 등) 해당 영상은 `failed / 영상 판단 불가`로 기록하고 다음 영상으로.

## 3. 캡션 작성

- 1문장: 후킹 (질문·감탄·궁금증 유발, 과장 금지)
- 본문 1~3문장: 영상에서 보이는 핵심 내용
- 마무리 1문장: 매장·제품·브랜드에 자연스럽게 관심을 갖게 하는 문장 (영상/설정에 근거)
- 과도한 광고 문구("최고", "무조건", "역대급" 남발) 금지. 이모지는 1~3개 이내.

## 4. 해시태그

- 8~15개. 브랜드명 / 매장명 / 지역명(config) + 영상에 나온 메뉴·서비스 + 주제 + 검색 가능성 높은 키워드.
- 영상과 무관한 인기 태그(#맞팔, #좋아요반사 등) 금지. 중복 금지. 공백 없이 `#태그` 형식.

## 5~9. Mirra 발행

### A. Mirra MCP가 있을 때
- 도구 목록에서 미디어 업로드 / 게시물 생성 / 계정 조회 / 발행 / 게시 상태 조회 기능을 찾아 사용한다.
- 계정 조회 결과에서 `config.accounts`와 **정확히 일치하는 계정만** 선택한다. 하나라도 매칭되지 않으면 중단.

### B. 브라우저로 진행할 때
1. https://www.mirra.my/ko/home 접속. 로그인 유지 상태를 사용한다. 로그인 화면이면 **사용자에게 직접 로그인을 요청**하고 기다린다(비밀번호를 입력하거나 만들지 않는다).
2. **콘텐츠 관리** 메뉴 → 새 콘텐츠 작성 화면.
3. 영상 업로드: 파일 선택 input에 로컬 경로를 지정. 진행률이 끝나고 미리보기/썸네일이 뜰 때까지 확인.
   - 실패 시 화면의 오류 문구를 그대로 기록(형식 미지원 / 용량 초과 / 네트워크 / 기타)하고 이 영상은 중단.
4. 작성란에 `캡션 + 빈 줄 + 해시태그` 입력 후, 입력란 값을 다시 읽어 원문과 글자 단위로 일치하는지 확인(누락·중복 확인).
5. 연결된 계정 중 `config.accounts`에 있는 계정만 체크. "전체 선택" 금지.
6. 버튼 위치가 바뀌었으면 좌표가 아니라 버튼/메뉴의 **텍스트와 문맥**(콘텐츠 관리, 업로드, 계정, 지금 발행 등)으로 다시 찾는다. 그래도 못 찾으면 `failed / 화면 구조 변경`으로 중단.

## 10. 발행 전 최종 검수 (모두 통과해야 진행)

- [ ] 업로드된 영상이 분석한 그 파일인가 (파일명/미리보기)
- [ ] 업로드 완료 상태인가
- [ ] 캡션이 원문과 일치하는가
- [ ] 해시태그가 원문과 일치하는가
- [ ] 오탈자·사실과 다른 문구가 없는가
- [ ] 선택된 계정 = `config.accounts` 인가 (초과·누락 없음)
- [ ] `publish-log.csv`에 같은 파일명/해시의 success 기록이 없는가

`config.confirm_before_publish`가 `true`(기본값)이면 검수표를 사용자에게 보여주고 승인을 받은 뒤에만 발행한다.

## 11. 지금 발행

- **지금 발행** 실행 후, Mirra의 성공 메시지 또는 콘텐츠 목록/발행 내역에서 해당 게시물이 "발행 완료(게시됨)" 상태인지 확인한다. 가능하면 게시물 URL을 확보한다.
- 버튼 클릭만으로 성공 처리하지 않는다. 상태를 확인할 수 없으면 `unknown`으로 기록하고 사용자에게 알린다(재발행하지 않는다 — 중복 위험).

## 12. 기록

```bash
python3 .claude/skills/mirra-publish/scripts/log_publish.py \
  --file "<파일명>" --sha256 "<해시>" --accounts "계정1;계정2" \
  --caption "<캡션>" --hashtags "#a #b" --status success|failed|unknown \
  [--post-url "<URL>"] [--error "<오류 내용>"]
```

성공·실패·unknown 모두 기록한다. 발행 시각은 스크립트가 자동으로 넣는다.

## 오류 시 원칙

다음은 임의로 처리하지 않고 기록 후 해당 영상 발행을 중단한다. 다른 영상은 계속 진행한다.
영상 판단 불가 · 발행 계정 불명확 · 로그인 실패 · 업로드 실패 · 중복 발행 의심 · 화면 구조 변경 · 발행 성공 확인 불가.

마지막에 처리 결과 요약표(파일명 / 계정 / 상태 / 비고)를 보여준다.
